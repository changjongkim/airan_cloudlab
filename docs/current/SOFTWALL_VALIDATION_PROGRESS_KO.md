# SoftWall 후속 스킴·강한 baseline 검증 기록 — 2026-09-22 UTC

**결론:** 원자적 복구 예약의 *자리 이동 자체*는 AI 수요 인지 greedy baseline도 재현한다.
공동 정책의 독립 우위는 아직 없다. 같은 GPU의 두 셀 경로에서 전체 conventional
host 결정→commit 반환 계측과 독립 채널 feature calibration은 통과했다. 그러나 첫
온라인 고 feature gate는 AI 처리량을 줄여 사전 성능 gate에 실패했다. 교차 endpoint
buffer 경로는 기능 canary를 통과했다. 어느 결과도 실제 MAC deadline, WCET, 강한
전체 결합 baseline 또는 공동 스킴의 GPU 우위를 입증하지 않는다.

## 현재 코드와 다음 검증

`FallbackCalendar`와 `DartRuntime`에 **복수 복구 credit의 원자적 재배치**를 추가했다.
선행 NeuralRx 작업이 물리적으로 완료됐다는 응답이 없는 요청의 credit은 이동할 수 없고,
전체 새 일정이 lane 충돌·요청 deadline을 만족해야 변경된다. 실패하면 모든 기존 예약이
남고, 오래된 reservation으로 해제하려 해도 새 credit을 지우지 않는다. 현재 CPU unit
test 21개가 통과했다. 재배치와 AI lease의 원자 transaction도 추가해 Confirm73/76에서
GPU 성공 경로를 확인했다. 이는 fault continuation이나 전체 공동 정책 검증은 아니다.
[별도 10,000회 fault 회귀](../../results/softwall_same_gpu/recovery_replan_runtime_faults_10000.json)도
wrong/stale/duplicate accept·over-admission·credit leak 없이 통과했다. 이 회귀는 새
재배치 경로의 모든 동시성 상태를 발생시키는 시험은 아니다.

**다음 GPU 비교 전에 필요한 자격 gate:** NRx·conventional뿐 아니라 AI unit의
실제 mode별 **host 전체 경로** 상한을 먼저 검증한다. Confirm90의 실제 25/12
달력은 NRx tail로 실패했고, Confirm91의 실제 30/12 달력은 예열·GC OFF 4셀
두 seed에서 통과했다. C91 원자료의 AI 261,031건은 8 ms 미만이었고,
Confirm95는 실제 AI8 달력을 두 새 seed에서 통과했다. 그 결과 7×8 ms AI와
NRx30·복구4×12·guard2의 보수 직렬 합은 136 ms로 D155 안에 들어간다.
Confirm96도 실행 가능 70/70 상태의 모든 정책이 AI 7개를 전부 수용함을
확인했다. 따라서 **현재 7-unit 단일 사건 경합 branch는 종료**한다. C95는
유한 표본 자격이지 WCET나 7-unit 원자 lease 실증은 아니다.

**다음 차별 gate:** 실제 물리 서비스 길이에서 AI 수요가 복구 의무와 경쟁하는
workload를 사전 등록한다. 가능한 경로는 더 긴 실제 AI 작업 class, 또는 개별
도착·마감이 다른 온라인 작업이다. 양 정책에는 동일 채널 feature·MPS cap·
all-fail 안전 판정기·정확한 AI/복구 recourse를 준다. 공동 greedy와 exact의
현 단일 사건 행동은 같으므로 exact 탐색 우위를 주장하지 않는다. 최소-NRx
단계별 baseline의 약점을 넘어서 **두 endpoint를 모두 쓰는 무선 이득 최대화
baseline**에도 사전 무선 비열등 조건과 AI 적시 완료 이득을 함께 증명해야 한다.
조건부 PHY 가치·복구 의무를 분리했을 때 차이가 사라지는지 확인하고, 실제
GPU ABBA 반복에서 유지되지 않으면 공동 정책 성능 우위 주장을 중단한다.

[구체적인 공동 스킴 판정](SOFTWALL_NOVELTY_SCHEME_DECISION_KO.md)은 MPS를 실행 기반으로
두고, NeuralRx의 conventional 대비 *추가* 무선 가치, 여러 셀의 조건부 복구 의무,
허용 AI unit을 한 온라인 결정으로 묶는다. 이 결합은 아직 연구 가설이다.

그 다음에야 (1) 현 온라인 feature의 host-to-decision 시간·두 endpoint 재배치,
(2) 미완료 NRx–AI/복구의 물리 co-run 상한 또는 GPU 완료 fence,
(3) 실제 대상 DU의 `d_MAC`, (4) 동일 trace paired baseline 대비 joint 실행을 확인한다.
Confirm57의 held-out neural-only 사례는 30/500이므로 0.4% 손실의 일반화 정밀도를
과대해석하지 않는다. 앞선 Aerial TDL-A 호환성 FAIL도 바뀌지 않았다.
